# pain001-mcp v0.0.79

## Highlights ⭐️

* **Scheme profiles an agent can actually use**: the `profile` and `scheme` parameters of `validate_payment_scheme`, `simulate_payment_batch` and `stage_payment_batch` now list every profile the installed pain001 ships (29 in 0.0.79), built from the core at import. `stage_payment_batch` used to suggest `sepa-instant`, `bacs` and `cbpr-plus`, which the core rejects; the real names are `sepa-inst`, `uk-bacs` and `cbpr-cross-border`.
* **Every statement, every transaction**: on pain001 0.0.79, `parse_pain002` returns every transaction of a partially accepted report and `parse_camt053` returns every statement in a file, now declared in its output schema so structured results keep them.
* **Complete message-type names**: `list_message_types` names `pain.001.001.13` and `pain.008.001.08` instead of repeating the raw type.
* **In lockstep with pain001 0.0.79**: requires `pain001[fast]` and `pain001-loader-mt101` 0.0.79, and the release page is now written by the release workflow in the suite's shape.

## Details

A test now fails when a tool description or schema quotes a scheme
profile the core does not have, or when a core message type has no
human name. The README links the licence texts that exist, ROADMAP.md
no longer calls 0.0.52 the current release, and the Glama description
names the UK and US rulebooks the core checks. The server still
registers 28 tools; generated XML is unchanged from 0.0.78.
